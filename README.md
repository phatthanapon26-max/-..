# Freshy Water v2 — การเชื่อมต่อและสิทธิ์ที่แก้ไขแล้ว

ชุดนี้ใช้ Supabase ตามโค้ดที่แนบมา ไม่ได้เชื่อม Google Sheets และ api/sheets.js จะตอบว่าฟังก์ชันนี้ไม่ได้เปิดใช้ เพื่อไม่ให้มี API รับ Private Key แบบไม่ตรวจสิทธิ์ค้างอยู่

## การเชื่อมต่อของชุดนี้
ชุดส่งมอบนี้ตั้งค่าโครงการ Supabase จริงไว้ใน deploy-config.js แล้ว และไฟล์ standalone ใช้ค่าเดียวกัน จึงเปิดเป็นโหมดออนไลน์เสมอแม้รีเฟรชหรือตัวเบราว์เซอร์ยังมีค่าโหมดสาธิตเก่าอยู่ Publishable Key เป็นคีย์สาธารณะสำหรับหน้าเว็บเท่านั้น ไม่มี Secret หรือ Service Role Key อยู่ในโค้ด

## ติดตั้งฉบับใหม่
1. อัปโหลดไฟล์ทั้งชุดขึ้น Vercel โดย index.html อยู่ root, api อยู่โฟลเดอร์ api, vendor และ deploy-config.js อยู่ครบ ไม่ต้องตั้ง ENV สำหรับล็อกอินหรือฐานข้อมูล Node.js 22 ขึ้นไป
2. ฐานข้อมูลและสิทธิ์ในโครงการจริงติดตั้งแล้ว บัญชีแอดมินต้องมีรหัสผ่านที่ใช้งานได้และยืนยันอีเมลแล้ว
3. เปิดเว็บไซต์และล็อกอินด้วยอีเมล/รหัสผ่านจริง ระบบจะอ่านและบันทึกผ่าน RPC ที่ตรวจสิทธิ์

ห้ามกรอก Service Role Key หรือ Secret Key ในหน้าเว็บ รหัส 7716 ใช้เฉพาะสาธิต โหมดออนไลน์จะไม่รับรหัสนี้แทนบัญชีจริง

## อัปเกรดฐานข้อมูลเดิม
สำรองข้อมูลเดิมก่อนรัน SQL SQL ใช้ตาราง freshy_store เดิมและคงข้อมูลเดิมไว้ แต่ปิดสิทธิ์อ่านเขียนโดยตรงและลบ policy แบบ anonymous เดิม ให้เข้าผ่าน freshy_read / freshy_apply เท่านั้น ต้องอัปเดตไฟล์หน้าเว็บทั้งชุดพร้อม SQL เพราะเวอร์ชันเก่าจะอ่านตารางโดยตรงไม่ได้

ตั้งค่าพนักงาน: สร้างบัญชีที่ Authentication → Users ก่อน แล้วเพิ่มพนักงานในหน้าจัดการพนักงานโดยใช้อีเมลเดียวกัน บทบาทและสิทธิ์อ่านข้อมูลจะตรวจในฐานข้อมูล พนักงานเปลี่ยนบทบาทของตัวเองไม่ได้

ฐานข้อมูลใหม่มีเฉพาะบัญชีแอดมินและการตั้งค่า ไม่มีข้อมูลลูกหนี้หรือยอดขายสาธิตถูกนำเข้า ให้กรอกข้อมูลสถานประกอบการ สินค้า ลูกค้า และพนักงานจริงก่อนเริ่มงาน

## การซิงก์และรีเฟรช
ค่าการเชื่อมต่อของชุดนี้มากับไฟล์ deploy-config.js จึงไม่หายเมื่อเปลี่ยนโดเมน ล้างข้อมูลเว็บไซต์ หรือรีเฟรช เซสชันออนไลน์เก็บใน sessionStorage และต่ออายุด้วย Supabase SDK

ส่งเฉพาะรายการที่เปลี่ยน แทนการเขียนทับทั้ง collection ฐานข้อมูลตรวจสำเนาก่อนแก้ หากอีกเครื่องเปลี่ยนรายการเดียวกันจะปฏิเสธทั้ง batch ข้อมูลรอส่งเก็บแยกตามบัญชี/โครงการและคงอยู่หลังรีเฟรช กด “ข้อมูลรอส่ง” เพื่อดาวน์โหลดสำเนา ลองส่งใหม่ หรือยืนยันใช้ข้อมูลออนไลน์ การใช้ข้อมูลออนไลน์จะทิ้งสำเนาที่แก้ในเครื่องตามคำยืนยันของผู้ใช้

ระหว่างเปิดฟอร์มแก้ไขหรือหน้าตั้งค่า ระบบพักการดึงข้อมูล เพื่อไม่ให้ฟอร์มถูกรีเซ็ตขณะกรอก การต่ออายุเซสชันยังทำงาน

## อีเมล
แอดมินตั้งค่า Resend API Key และอีเมลผู้ส่งที่ยืนยันโดเมนแล้วในหน้าอีเมลได้ API จะตรวจบัญชี/บทบาทจาก Supabase ก่อนส่ง และอ่านค่าจากฐานข้อมูลที่ได้รับสิทธิ์ ไม่รับ API Key หรือ SMTP Host จากเนื้อหาคำขอ

สำหรับอีเมลแจ้งเตือนที่พนักงานเป็นผู้ดำเนินการ: ตั้ง SUPABASE_URL, RESEND_API_KEY และ MAIL_FROM ที่ Vercel เพื่อให้เซิร์ฟเวอร์ส่งได้โดยไม่เปิดเผย API Key ให้พนักงาน ตัวเลือก SMTP ต้องตั้ง SUPABASE_URL, SMTP_HOST, SMTP_USER, SMTP_PASSWORD และ SMTP_PORT (587 หรือ 465) ที่เซิร์ฟเวอร์ด้วย การตั้งค่า ENV นี้ใช้สำหรับอีเมลเท่านั้น

### รายงานผู้บริหารอัตโนมัติ 08:00 และ 18:00 น.
ไฟล์ vercel.json ตั้งเวลาไว้เป็น 01:00 และ 11:00 UTC ซึ่งตรงกับ 08:00 และ 18:00 น. ประเทศไทย ระบบส่งสรุปยอดสำคัญไว้ในเนื้อหาอีเมลและแนบ PDF จึงอ่านได้ทั้งแบบเปิดอีเมลทันทีหรือดาวน์โหลดเอกสาร

ตั้ง Environment Variables ฝั่ง Vercel: `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `RESEND_API_KEY`, `MAIL_FROM`, `CRON_SECRET` และ `REPORT_TO` (ถ้าไม่ตั้ง REPORT_TO ระบบใช้อีเมลแอดมินในฐานข้อมูล) ค่าลับเหล่านี้ต้องอยู่ฝั่งเซิร์ฟเวอร์เท่านั้น ห้ามใส่ใน deploy-config.js หรือหน้าเว็บ

สถานะ “ผู้ให้บริการรับอีเมลแล้ว” ยืนยันการรับคำขอของผู้ให้บริการ ไม่ยืนยันว่าเข้ากล่องจดหมายผู้รับแล้ว ถ้าผู้ให้บริการปฏิเสธจะบันทึกสถานะไม่สำเร็จ ผู้รับรายงานใช้ค่าที่กรอกในฟอร์มจริง

## ตรวจสอบแล้ว
- Browser: เข้าสู่ระบบสาธิต/ออนไลน์, รีเฟรช, ไม่อัปโหลดข้อมูลสาธิต, บันทึกโปรไฟล์, ข้อมูลรอส่งยังอยู่หลังรีเฟรช, ไม่ล้นแนวนอนบนมือถือ
- SQL บน PostgreSQL ผ่าน PGlite: ปฏิเสธ anon/บัญชีนอกระบบ, จำกัดข้อมูลตามเจ้าของ, ปฏิเสธการเพิ่มสิทธิ์ตัวเอง, ปฏิเสธการแก้เงินสดหลัง 2 นาที, ห้ามพนักงานย้อนรายการจ่ายแล้ว, ตรวจความขัดแย้ง, rollback ทั้ง batch
- Email API: ตรวจบัญชี/สิทธิ์/ผู้รับ, ปฏิเสธ host ที่ไม่อนุญาต, ตรวจผลจริงจากคำตอบผู้ให้บริการ

ฐานข้อมูลจริงติดตั้งและตรวจสิทธิ์แล้ว แต่ชุดไฟล์นี้ยังไม่ได้ติดตั้งบนโดเมนสาธารณะ และยังไม่ได้ส่งอีเมลจริง

การซ่อนหน้าจอเมื่อออกจากหน้าต่างช่วยลดการเปิดเผยข้อมูล แต่ไม่สามารถรับประกันการป้องกันภาพหน้าจอของระบบปฏิบัติการได้
