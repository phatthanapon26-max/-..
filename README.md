# Freshy Water 8.0

ระบบจัดการลูกหนี้ โรงน้ำดื่ม เฟรชชี่ วอเตอร์ ใช้ Supabase Auth และ RPC เดิมสำหรับข้อมูลจริง ไม่มีการล้างข้อมูลหรือสร้างข้อมูลจำลองระหว่าง deploy

## การออกแบบและงานประจำวัน

- พื้นขาว เขียว แดง ส้ม เหลือง พร้อมโหมดมืดที่เปลี่ยนทันทีและเคารพ reduced motion
- ฟอร์มลูกหนี้รองรับมือถือ หมู่บ้านเลือกหรือพิมพ์ได้ รหัสเดิมคงเดิม รหัสใหม่สร้างให้อัตโนมัติ
- หลังบันทึกลงฐานข้อมูลสำเร็จ ถามเพิ่มต่อ: Enter ยืนยัน Backspace/Delete จบ เฉพาะกล่องยืนยัน
- รูปโปรไฟล์เลือก JPG/PNG/WebP ในเครื่องและย่อเป็น 256px ก่อนเก็บในฐานข้อมูล
- CSV ภาษาไทย UTF-8 BOM จากข้อมูลตามตัวกรอง พร้อมป้องกันสูตรในช่องข้อความ
- รายการลูกหนี้แสดงครั้งละ 30 รายเพื่อลดภาระเมื่อมีประมาณ 1,000 ลูกหนี้
- รีเซ็ตเฉพาะรายการ `isDemo:true` เก็บข้อมูลจริง ผู้ใช้ สินค้า หมู่บ้าน และค่าตั้งค่าเดิม

## เอกสารและ QR

เอกสาร A4 พื้นขาว ตัวอักษรดำ มีเลขอ้างอิง ตาราง และช่องลงนาม ทุกคำสั่งพิมพ์เปิดตัวเลือก QR มุมบนขวาไว้ให้ รายงานลูกหนี้แยกตารางและยอดรวมรายคน พร้อมยอดรวมท้ายรายงาน รูปแบบราชการใช้ Sarabun สีดำบนกระดาษขาว หัวเรื่องกึ่งกลาง เลขอ้างอิง วันที่ ตารางเส้นบาง และช่องลงนาม รูปแบบเดียวกันทั้งรายงานลูกค้า ลูกหนี้ เงินสด ประวัติพนักงาน รายงานประจำวัน และหน้าดูเอกสาร

QR อ้างอิงสำเนาเอกสารและรหัสสุ่ม 256 บิต หากไม่มี Service Role Key ระบบใช้ RPC และสิทธิ์บัญชีเดิมเก็บเอกสารใน sentEmails ประเภท document ผู้สแกนต้องเข้าสู่ระบบ แอดมินอ่านได้ทั้งหมด พนักงานอ่านได้เฉพาะเอกสารที่ตนออก ไม่ต้องตั้งค่าฐานข้อมูลเพิ่มหรือเพิ่มสิทธิ์สาธารณะ หน้าดูเอกสารมีปุ่มพิมพ์ / บันทึก PDF และ QR ของเอกสารฉบับเดิม การพิมพ์ซ้ำไม่ออกเลขใหม่ เอกสารไม่แสดงปะปนในประวัติอีเมล การติดตั้งเดิมที่มี Service Role Key ยังคงรองรับเอกสารสาธารณะตามพฤติกรรมเดิม เลขเอกสารใหม่ไม่แก้ settings ของพนักงาน

## ตั้งค่าเซิร์ฟเวอร์ Vercel

ตั้ง Environment Variables สำหรับ production แล้ว redeploy:

- `SUPABASE_URL`: URL โครงการเดิม
- `SUPABASE_SERVICE_ROLE_KEY`: เก็บที่เซิร์ฟเวอร์เท่านั้น ใช้กับเอกสารสาธารณะในการติดตั้งเดิม, สำรองเอกสาร, เลือกบัญชีพนักงานจากรหัสบนเครื่องใหม่, หมู่บ้านใหม่ของพนักงาน และรายงานตามเวลา ไม่จำเป็นสำหรับ QR ที่ใช้สิทธิ์บัญชีเดิม
- `CRON_SECRET`: ค่าสุ่มลับสำหรับ Vercel cron

URL/Anon Key สาธารณะอยู่ใน deploy-config.js ห้ามใส่ Service Role Key ในไฟล์นั้นหรือหน้าเว็บ

API ยืนยันสมาชิกด้วย freshy_read ของโครงการที่ตรึงไว้ ไม่รับโครงการหรือ SMTP host ตามคำขอจากผู้เรียก SMTP อ่านค่าที่ผู้ดูแลบันทึกในฐานข้อมูลก่อนใช้ค่าจากเซิร์ฟเวอร์

## อีเมล Google

หน้าการตั้งค่า → อีเมลแจ้งเตือน → เลือก Google Gmail ระบุอีเมลผู้ส่ง, Gmail App Password 16 ตัว, อีเมลผู้รับ และประเภทกิจกรรม ไม่ต้องใช้ API Key แต่บัญชี Google ต้องเปิด 2-Step Verification และสร้าง App Password ระบบเก็บการตั้งค่าในฐานข้อมูล แอดมินเห็นค่าลับ พนักงานไม่ได้รับรหัสผู้ส่ง

บัญชีผู้ส่งตั้งค่าครั้งแรกเพียงครั้งเดียวแล้วใช้ร่วมกันทุกเครื่อง กลุ่มผู้รับรองรับอีเมลสูงสุด 10 รายการ คั่นด้วยจุลภาค อัฒภาค หรือขึ้นบรรทัดใหม่ ระบบบันทึกข้อมูลออนไลน์ก่อนส่งและแสดงข้อผิดพลาดให้เห็นในหน้าต่างรายงาน รายงานลูกค้าจ่ายสดส่งรายละเอียดตามวันที่ที่เลือก แบบทางการ (ตัวเลือกเริ่มต้น) ส่งอีเมลแจ้งนำส่งเอกสารและสร้าง PDF แนบจากข้อมูลชุดเดียวกันที่เซิร์ฟเวอร์ แบบเรียบง่ายส่งเนื้อหาโดยไม่แนบ PDF หากสร้าง PDF ไม่สำเร็จจะไม่ส่งอีเมล

เวลารายงานเริ่มต้น 08:00 และ 18:00 น. เลือกได้ 1–4 รอบ ใช้เวลาประเทศไทย และบันทึกสถานะป้องกันส่งซ้ำรอบเดียวกัน

Vercel cron ตรวจงานวันละหนึ่งครั้งในแต่ละช่วงชั่วโมงทั้งหมด 24 รายการ ระยะเวลาคลาดเคลื่อนขึ้นกับแผน Vercel; แผน Hobby ไม่รับประกันส่งตรงนาที เบราว์เซอร์แอดมินที่เปิดอยู่ช่วยตรวจงานทุกนาทีเมื่อเปิดรายงานตามเวลา

## สำรองข้อมูล

วันที่ 1, 15 และ 31 ตามเวลาประเทศไทย หากปิดระบบจะทำรอบล่าสุดเมื่อแอดมินเปิดระบบอีกครั้ง เดือนที่ไม่มีวันที่ 31 จะข้ามวันนั้น

เลือกโฟลเดอร์ในเครื่องผ่านเบราว์เซอร์ที่รองรับ File System Access เพื่อเขียนไฟล์และตรวจอ่านกลับได้ หากไม่รองรับจะเริ่มดาวน์โหลดตามปกติและต้องตรวจไฟล์ใน Downloads การดาวน์โหลดอัตโนมัติอาจต้องอนุญาตในเบราว์เซอร์ ระบบไม่สามารถเขียนลงเครื่องที่ปิดเบราว์เซอร์อยู่

สำรองข้อมูลหลักจากการอ่านออนไลน์ล่าสุด และอ่านเอกสารเพิ่มเป็นส่วนย่อยเพื่อหลีกเลี่ยงขีดจำกัด response ของ Vercel หากเซิร์ฟเวอร์อ่าน QR ไม่ครบ ไฟล์จะมี warning และแจ้งให้ทราบ ห้ามถือว่าเป็นไฟล์สำรองครบชุด

การกู้คืนข้อมูลหลักจะผสานตาม id และคงการเชื่อมต่อโครงการเดิม เก็บสำเนา rows ในไฟล์ไว้สำหรับกู้คืนเอกสาร QR ที่เซิร์ฟเวอร์

## ประวัติการแก้ไข

แอดมินดูทุกคนในโรงงานหรือเลือกพนักงานจากชื่อได้ รวมชื่อของพนักงานที่ไม่อยู่ในรายชื่อปัจจุบันแล้ว แสดงครั้งละ 50 รายการพร้อมปุ่มเปลี่ยนหน้า ไม่มีข้อจำกัดเฉพาะ 200 รายการล่าสุด ยังคงสิทธิ์แอดมินและกฎฐานข้อมูลเดิม
